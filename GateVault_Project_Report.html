1. Executive Summary & Core Value Proposition
Overview

GateVault is an enterprise-grade digital logistics and security platform engineered specifically for gated high-rise residential complexes. In modern communities, security gatehouses face hundreds of courier and food deliveries daily. Without an automated verification chain, properties suffer from gate congestion, lost or misplaced packages, unverified collections by unauthorized individuals, overflowing parcel shelves, and persistent resident inquiries.

Core Solution: Verifiable Digital Chain of Custody

GateVault completely replaces physical paper delivery registers with an unbroken digital custody trail:

1 Courier Arrival: Delivery agent arrives at gatehouse with parcel or food delivery.
2 Intake & Barcode Match: Guard scans/enters tracking number or performs fast manual intake (Tower & Flat).
3 Smart Shelf Assignment: System checks live capacity and assigns an available shelf slot (e.g., S-04).
4 Secure PIN Generation: Unique Parcel ID (GV-2026-XXXXXX) and private 4-digit PIN generated; resident notified.
5 Resident Verification: Resident (or authorized flatmate) presents the 4-digit PIN at the gate terminal.
6 Handover & Audit Logging: Guard confirms handover; immutable verification record logged with guard and timestamp.
Key Architectural Achievement: Zero-state dependency. Occupancy is derived directly from live database parcel records rather than manually maintained counter fields, eliminating data drift or race-condition storage mismatches.

5. Technical Audit, Discrepancies & Recommendations
Audit Findings
1. Database Engine Mismatch (SQLite vs MySQL):
The file setup_db.py and backend/.env specify MySQL credentials (DB_NAME=gatevault, DB_USER=root, DB_PASSWORD=Saivinay2027). However, settings.py is explicitly configured to use SQLite:
DATABASES = {'default': {'ENGINE': 'django.db.backends.sqlite3', 'NAME': BASE_DIR / 'db.sqlite3'}}
Impact: The application is currently operating flawlessly on SQLite using backend/db.sqlite3 (282 KB). To switch to MySQL, update settings.py to read the .env database configuration and ensure the MySQL service is active.
2. Demo Data Execution Syntax:
The project README.md references running python generate_demo_data.py. Because the script is structured as a Django management command in api/management/commands/generate_demo_data.py, it should be executed using:
python manage.py generate_demo_data
